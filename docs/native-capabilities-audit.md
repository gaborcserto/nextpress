# NATIVE-01 — Native Capabilities & Dependency Audit

## Executive summary

NextPress already uses the platform effectively at its main boundaries. Web uses Server Components and request-scoped reads, Admin uses native dialogs and form controls, and API uses native HTTP and stream primitives around explicit authorization and publication rules. The largest safe simplifications are local. Surface parent-selector failures separately from empty data, retire the one-file Sass pipeline, and verify stale ESLint declarations before removing them. Keep Slate, Sharp, Better Auth, Prisma, and Admin's Temporal polyfill. Prioritize interaction and failure-state verification ahead of introducing new abstractions.

This source audit covers baseline `4983f0d` and the FUNC-04 and TIME-01 decisions. It used the installed tree, lockfile, tracked imports, routes, configs, schemas, existing test coverage and historical local notes. The earlier architecture reuse and tooling audits informed the search. Their workspace and version observations were checked against current source. The local reference monorepo served as tooling context. Findings here derive from NextPress. No production changes, browser runs, database query plans, or performance benchmarks were made during the audit.

## Detailed findings

### N01 · Distinguish an unavailable parent list

[HierarchyField](../apps/admin/src/ui/components/HierarchyField/HierarchyField.tsx#L10) initializes options to an empty list and sets the same list after any `jsonResult` error. The select consequently presents only “(no parent)” during both failure and a genuine empty result. This is a demonstrated source-level correctness and accessibility issue. Keep the native select and store a request result with explicit loading, empty, error and success states. Offer retry with an accessible message and preserve the selected parent during failures. The parent API remains authoritative. Verify empty success, preselected parent, malformed response, unauthorized response, retry, and unmount. An async effect is appropriate for this network synchronization.

### N02 · Use a standard CSS Module

[public-ui.module.scss](https://github.com/gaborcserto/nextpress/blob/4983f0da231b217723aed308f67e8e9fd4405fbf/apps/web/src/components/public-ui/public-ui.module.scss) is the sole tracked SCSS file. `Container`, `Stack`, `ActionButton`, `ActionLink`, and `SkipLink` import it. Its only Sass-shaped constructs are two nested pseudo-class selectors on `.action`. Use flat `.action:hover` and `.action:focus-visible` selectors in a CSS Module. Flattening avoids changing the browser floor or cascade specificity. Update imports and remove Web's Sass declaration with npm after a production build confirms there are no other consumers. Verify all presets, both themes, focus and hover states, disabled buttons and skip-link positioning. The demonstrated benefit is fewer build dependencies. Build and bundle improvements have no measurement. [Standard CSS nesting](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Nesting/Using).

### N03 · Verify the ESLint compatibility declarations

Root [package.json](../package.json) and [ESLint config manifest](../packages/eslint-config/package.json) both declare `@eslint/eslintrc`. Tracked searches for `FlatCompat` and direct package references yielded only declarations for the package name and no call sites. Flat config is already the repository convention. Check clean-install resolution of each workspace config, the hook and any third-party config's peer expectations before dropping these entries. An indirect installation may still be required by ESLint. Verify all workspace lint tasks, format and readability suites, and isolated staged-hook fixtures. Benefit is accurate ownership of tooling requirements.

### N04 · Parse the seed flag locally

[seed.ts](../packages/db/prisma/seed.ts#L119) first calls `loadApiEnvironment`, then uses dotenv to populate a separate object for the fallback `ALLOW_DEVELOPMENT_CONTENT_SEED` value. Node 24 `readFileSync` plus `node:util.parseEnv` can parse into a local object. `process.loadEnvFile` would change process-wide values and is unsuitable here. Keep `loadApiEnvironment` in [api-environment.ts](../packages/db/src/api-environment.ts) because its Next environment file precedence and expansion serve a different contract. Preserve external flag precedence, missing file behavior, database target validation, and fail-closed production guards. Compare BOM, quoting, multiline, duplicate keys and unreadable-file behavior before removing direct dotenv. Verify seed policy and target selection with isolated fixtures. [Node 24 parseEnv](https://nodejs.org/docs/latest-v24.x/api/util.html#utilparseenvcontent).

### N05 · Cancel obsolete reads consistently

[HierarchyField](../apps/admin/src/ui/components/HierarchyField/HierarchyField.tsx#L16) and [useTagMultiSelectSearch](../apps/admin/src/features/taxonomy/TagMultiSelect/TagMultiSelectSearch.hook.ts#L27) ignore late completions via local flags. Settings, [UsersScreen hooks](../apps/admin/src/features/users/UsersScreen/UsersScreen.hooks.ts), health and Live Preview already pass real signals. [jsonResult](../apps/admin/src/lib/api/client.ts#L33) accepts `RequestInit`. Use that existing cancellation path for parent reads and assess passing a signal through Admin's tag loader contract. Keep the 200 ms debounce and result identity check because cancellation alone cannot guarantee ordering for a loader that has already completed. Avoid a generic request hook. Test rapid typing, old responses, loader changes, unmount and aborted reads without spurious error announcements. Fewer obsolete requests is a likely opportunity.

### N06 · Retain native dialogs and shared controls

[useModalDialog](../apps/admin/src/ui/hooks/useModalDialog.ts) uses `showModal` in a layout effect. [ConfirmDialog](../apps/admin/src/ui/primitives/ConfirmDialog/ConfirmDialog.tsx), MediaDialog and the shell drawer already use native modals. Keep the semantic controls in Inputs, Select, Buttons and [SortableHeader](../apps/admin/src/ui/components/DataList/SortableHeader.tsx#L62), which gives sorting an interactive button and exposes `aria-sort`. Tailwind and daisyUI provide the existing responsive styles. FormGrid, ToastHost and SkeletonBox address layout, live feedback and loading presentation. Native constraint attributes complement Zod and server field errors. Test focus entry and return, Escape, rejection while pending, nested pickers, disabled controls, live announcements, 200% zoom and mobile keyboard. The date picker has additional focus behavior and deserves separate coverage. [HTML dialog](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog).

### N07 · Evaluate popovers for simple disclosures

[Dropdown](../apps/admin/src/ui/primitives/Dropdown/Dropdown.tsx) manages open state, keyboard interaction and dismissal. [HeaderSearch](../apps/web/src/components/public-shell/HeaderSearch/HeaderSearch.tsx) and [PreferenceChoice](../apps/web/src/components/public-shell/PreferenceChoice/PreferenceChoice.tsx) each manage interaction locally. [MenuDisclosure](../apps/web/src/templates/blog/navigation/MenuDisclosure/MenuDisclosure.tsx) already builds on details/summary with Escape behavior. Trial Popover API light dismissal on one simple non-modal surface during DS-01. Keep explicit accessible names, menu keyboard rules where appropriate, focus return, workable SSR markup and a normal destination or control when JS is unavailable. Popover behavior and CSS anchor positioning have separate support requirements. Test mobile touch, zoom, clipping and screen readers before migrating. Keep [BlogNavigation](../apps/web/src/templates/blog/navigation/BlogNavigation/BlogNavigation.tsx)'s measurement until container queries can preserve the actual overflow grouping and link order. [Popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API).

### N08 · Keep Temporal in the picker

[publication-time.ts](../apps/admin/src/features/content/PublicationDatePicker/publication-time.ts), [PublicationDatePicker](../apps/admin/src/features/content/PublicationDatePicker/PublicationDatePicker.tsx) and [site-date-time.ts](../packages/shared/src/site-date-time.ts) split local-time conversion from Intl validation/display. [EventFields](../apps/admin/src/features/pages/EventFields/EventFields.tsx#L31) already uses native datetime-local input. It supplies a wall-time string. The scheduling picker must resolve it in the configured site zone and distinguish DST gaps from overlaps with explicit offset choices. Local Node reported `typeof Temporal === "undefined"`. Browser availability remains uneven. Keep the polyfill and ISO instant contract and preserve UTC timestamp semantics in [ADR-005](decisions/005-site-timezone-and-publication-instants.md). Revisit only after the runtime floor covers equivalent behavior. Check DST gaps and overlaps, unusual offsets, formatter locale/zone options, server-rendered time markup, hydration, and scheduled eligibility at the boundary. Profile formatter construction before promoting a cache. [Temporal](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Temporal).

### N09 · Keep Slate's document and selection model

[SlateEditor](../apps/admin/src/ui/components/SlateEditor/SlateEditor.tsx), [SlateToolbar](../apps/admin/src/ui/components/SlateEditor/SlateToolbar.tsx) and [slate.utils.ts](../apps/admin/src/ui/components/SlateEditor/slate.utils.ts) use Slate's editor, history, marks and transforms. `toggleBlock`, `unwrapSelectedLists` and `toggleHeading` own application-specific list and heading rules. Shared [page-document.ts](../packages/shared/src/editorial/page-document.ts) and Web [RichContent](../apps/web/src/components/RichContent/RichContent.tsx) preserve a stored content contract with media/link handling. Review toolbar command and selection behavior before sharing any repeated transform sequence. Slate transforms provide mechanics for wrap, unwrap and selection, while stored schema rules and URL safety checks remain application responsibilities. Verify undo/redo, IME, keyboard-only toolbar use, selection through pickers, nested lists, headings, links, images, documents, saved revisions and previews. Slate rerender cost is a hypothesis for PERF-01. [Slate transforms](https://docs.slatejs.org/api/transforms).

### N10 · Preserve request-scoped reads

[public-content.server.ts](../apps/web/src/lib/content/public-content.server.ts#L61), [PublicWebsiteShell](../apps/web/src/components/public-shell/PublicWebsiteShell/public-navigation.server.ts) and [public-site-settings.server.ts](../apps/web/src/lib/settings/public-site-settings.server.ts) cache parsed public data within a render. [fetchPublic](../apps/web/src/lib/content/public-api.server.ts) uses native fetch with no-store. [Admin session](../apps/admin/src/lib/auth/session.server.ts#L88) uses separate request-local memoization for session and provider reads. Next fetch can memoize identical render GETs, while React cache can also reuse parsing and domain projection. Retain both boundaries and the authoritative API HTTP hop. Verify metadata/page/shell request counts, locale and path distinctions, two sessions, immediate menu edits and unpublication. Duplicate wire requests remain a measurement question. [Next.js data fetching](https://nextjs.org/docs/app/getting-started/fetching-data), [React cache](https://react.dev/reference/react/cache).

### N11 · Measure archive enhancement tradeoffs

[LoadMorePostList](../apps/web/src/components/public-content/PostList/LoadMorePostList/LoadMorePostList.tsx) uses hydration detection, an accessible fallback link, client state for appended rows and a popstate reload. [getNextPostBatch](../apps/web/src/app/posts/actions.ts) is a targeted Server Function for public data. Keep normal link pagination and the preview-specific loader. Investigate Next's native history integration only against real Back/Forward restoration, deep links, focus placement and live announcement. An optimistic transition cannot provide confirmed results or reliable ordering by itself. Compare server-only archive and enhanced JavaScript/hydration costs before selecting a narrower client boundary. [Next.js native history integration](https://nextjs.org/docs/app/getting-started/linking-and-navigating#native-history-api).

### N12 · Keep publication-aware media delivery

[ContentMediaImage](../apps/web/src/components/public-content/ContentMediaImage/ContentMediaImage.tsx) combines unoptimized Next Image, native lazy/eager behavior, observer-driven preview handling, abortable fetch and object URL cleanup. [Web media handler](../apps/web/src/app/media/[id]/route.ts) forwards scoped requests. API public and protected media routes gate bytes separately. [RichContent](../apps/web/src/components/RichContent/RichContent.tsx) and [API rich-content projection](../apps/api/src/lib/public/rich-content.ts) should retain their rendering and publication responsibilities. Replacing this with the generic optimizer would lose source auth forwarding and timely revocation. Verify anonymous, editor and preview authorization, unpublish, image intrinsic sizing, animated GIF opt-in, protected PDF attachment headers and Blob URL cleanup. Keep CSP preview-only blob allowances and exact Admin origin. See [ADR-002](decisions/002-media-storage-and-delivery.md) and [ADR-003](decisions/003-pdf-document-assets.md). [Next image](https://nextjs.org/docs/app/api-reference/components/image).

### N13 · Retain streaming forwarding and log boundaries

[forwardApiRequest](../apps/admin/src/lib/api/upstream.server.ts#L38) uses URL, Headers, streams, `AbortSignal.any` and `AbortSignal.timeout`. It selects forward headers, preserves multiple cookies, removes stale compressed metadata, signs correlation and emits private/no-store responses. API [request log context](../apps/api/src/lib/api/request-log-context.server.ts), [request logging](../apps/api/src/lib/api/request-logging.server.ts) and Shared [request correlation](../packages/shared/src/request-correlation.ts) retain ownership of trustworthy correlation and structured failures. A rewrite alone cannot express this policy. Preserve errors and logs across routes. Verify timeout vs caller abort, cookie preservation, stream cancellation, request ID correlation and redaction. [Node 24 globals](https://nodejs.org/docs/latest-v24.x/api/globals.html).

### N14 · Keep version-checked saves and ID-based destinations

[PageHierarchy](../apps/admin/src/features/pages/PageHierarchy/PageHierarchy.tsx), [MenusScreen](../apps/admin/src/features/menus/MenusScreen/MenusScreen.tsx), [pageRepo](../apps/api/src/lib/repos/pageRepo.ts#L411), and [saveMenu](../apps/api/src/lib/repos/navigation.ts#L84) separate editing from serialized writes. Prisma transactions and PostgreSQL advisory transaction locks couple version or previous-position checks with updates. [Schema](../packages/db/prisma/schema.prisma) enforces references, uniqueness and parent-indexed ordering. Business rules cover cycles, maximum depth, Home placement and publication-visible ancestors. Preserve keyboard controls alongside any future drag enhancement. Verify competing writes, repeat saves, rollback, depth and cycle rejection, subtree visibility, locale URLs after move, preview menus, stable destination IDs and restrict-on-delete. [ADR-004](decisions/004-navigation-and-page-hierarchy.md), [PostgreSQL 18 locks](https://www.postgresql.org/docs/18/explicit-locking.html), [Prisma transactions](https://www.prisma.io/docs/orm/prisma-client/queries/transactions).

### N15 · Measure before query or pagination changes

[searchPublishedContent](../apps/api/src/lib/public/search.server.ts), [publishedPagePaths](../apps/api/src/lib/repos/page-hierarchy.ts#L19), [content-list service](../apps/api/src/lib/services/content-list.server.ts) and [dashboardRepo](../apps/api/src/lib/repos/dashboardRepo.ts) are entry points for query-plan and call-count review. PostgreSQL 18 recursive CTEs and cycle diagnostics could reduce hierarchy round trips if representative data demonstrates a bottleneck. Prisma select and batching, stable tie-breakers, existing indexes and bounded offset pagination are the starting point. Cursor pagination changes URL and result-snapshot behavior. Verify plans and Prisma query counts at several content sizes, broad and selective queries, deep ancestry, boundary pages and publication filters before considering SQL or index changes. No N+1 cost or index deficiency was established by timing. [PostgreSQL 18 recursive queries](https://www.postgresql.org/docs/18/queries-with.html).

### N16 · Import the existing slug behavior directly

Admin [slugify](https://github.com/gaborcserto/nextpress/blob/4983f0da231b217723aed308f67e8e9fd4405fbf/apps/admin/src/lib/utils/slugify.ts) and API [slugify](https://github.com/gaborcserto/nextpress/blob/4983f0da231b217723aed308f67e8e9fd4405fbf/apps/api/src/lib/utils/slugify.ts) re-export Shared's [slugify](../packages/shared/src/utils/slugify.ts). Direct imports can make ownership clearer once internal callers and tests move. Preserve Unicode normalization, generated slugs, collision behavior and legacy routes. Other URL and list lookalikes span different contracts. Public URL building is locale aware, Admin filters use private list queries, API has role-scoped error mapping, and Web unwraps public transport errors into rendering decisions. Retain those ownership boundaries. Verify accented, punctuation-only and repeated separator fixtures and unchanged public links.

### N17 · Keep auth and schema boundaries

[auth-server](../apps/api/src/lib/auth/auth-server.ts), [password.server](../apps/api/src/lib/auth/password.server.ts), [mutation.server](../apps/api/src/lib/api/mutation.server.ts), [rate-limit.server](../apps/api/src/lib/security/rate-limit.server.ts) and [openapi.ts](../apps/api/src/lib/api/openapi.ts) show distinct authentication, role, trusted-origin, throttling, and validation responsibilities. Native crypto functions cannot transparently replace existing bcrypt hash verification. Native forms and Response.json do not express policy or derive OpenAPI schemas. Keep Better Auth, bcryptjs and Zod. Local throttling has process scope. Review deployment-wide enforcement independently when horizontal scaling is in scope. Verify legacy password sign-in, roles, cross-origin rejection, rate-limit identity, stable public errors and OpenAPI coverage.

### N18 · Preserve SWR and editor lifecycle

[useContentList](../apps/admin/src/hooks/useContentList.ts), [useLegacyEditor](../apps/admin/src/features/content/editor/useLegacyEditor.ts), [DashboardScreen](../apps/admin/src/features/dashboard/DashboardScreen/DashboardScreen.tsx) and [MediaBrowser](../apps/admin/src/features/media/MediaBrowser/MediaBrowser.tsx) use SWR for cache/revalidation and request state. [usePrivateDraft](../apps/admin/src/features/content/private-drafts/usePrivateDraft.ts), [useUnsavedChanges](../apps/admin/src/features/content/editor/useUnsavedChanges.tsx), the Post/Page forms and [RevisionEditor](../apps/admin/src/features/content/RevisionEditor/RevisionEditor.tsx) have domain state covering versioned writes, editable fields, navigation and unsaved changes. Keep focus/retry/revalidation and explicit conflict behavior. React Actions, transitions or optimistic state can simplify a bounded interaction once its behavior is shown. They do not model save retries, publication or revision preconditions. Test focus revalidation, list sort/filter and pagination, out-of-order responses, conflict, dirty navigation and record change before removing any effects or memoization.

### N19 · Defer persistent caching and streaming changes

[Web layout](../apps/web/src/app/layout.tsx#L28) requests dynamic rendering, [public API client](../apps/web/src/lib/content/public-api.server.ts) uses no-store, and [search loading boundary](../apps/web/src/app/search/loading.tsx) already provides route-level pending UI. Next 16 Cache Components and tags require a deliberate policy for expiry, all publication and permission mutations, scheduled eligibility and multiple self-hosted instances. Keep current policy. PERF-01 can trace where settings, navigation and content block the shell, test a scoped Suspense boundary, measure metadata and 404 response behavior, and verify reverse-proxy buffering. Persistent caching of private or revocable content needs a complete isolation and invalidation model. [Next.js use cache](https://nextjs.org/docs/app/api-reference/directives/use-cache), [Next.js self-hosting](https://nextjs.org/docs/app/guides/self-hosting).

### N20 · Keep media inspection and bounded concurrency

[normalizeMediaImage](../apps/api/src/lib/services/media-image.server.ts#L90), [media-gif.server.ts](../apps/api/src/lib/services/media-gif.server.ts), [uploadDocument](../apps/api/src/lib/services/document-upload.server.ts#L188), and [media-storage.server.ts](../apps/api/src/lib/services/media-storage.server.ts) combine native bytes, filesystem and Web APIs with Sharp and qpdf. Preserve decode limits, MIME and signature checks, EXIF stripping, GIF composition, attachment delivery and cleanup on failure. Native File, Blob and FormData help transport files. They supply neither trustworthy inspection nor sanitization. Keep process and request deadlines, bounded buffering and storage ownership. Test invalid MIME, excessive decoded size, animation handling, validator absence, aborted uploads, concurrent requests and cleanup. Consider ranges or conditional responses only with equivalent reauthorization. [qpdf 12.4 CLI](https://qpdf.readthedocs.io/en/12.4/cli.html).

### N21 · Keep cross-platform and test tooling

Root [package.json](../package.json), API [package.json](../apps/api/package.json) and DB [package.json](../packages/db/package.json) show why cross-env and tsx exist. Node 24 type stripping cannot claim parity with runner resolution, import aliases and transformation without checking each script entry. Node test cannot replace Vitest, jsdom, Testing Library and Playwright features without migrating evidence and fixtures. Defer. If revisited, test clean checkout on Windows and Linux, module resolution, ESM/CJS, Prisma scripts and exit status propagation. [Node 24 TypeScript support](https://nodejs.org/docs/latest-v24.x/api/typescript.html).

### N22 · Keep native App Router conventions

[Catch-all Pages](../apps/web/src/app/%5B...segments%5D/page.tsx), [legacy Page route](../apps/web/src/app/pages/%5Bslug%5D/page.tsx), [robots](../apps/web/src/app/robots.ts), [sitemap](../apps/web/src/app/sitemap.ts) and [layout](../apps/web/src/app/layout.tsx) already use native routes, metadata, not-found behavior and font handling. [Web Proxy](../apps/web/src/proxy.ts) localizes requests and [Admin Proxy](../apps/admin/src/proxy.ts) handles shell-facing routing. Server components and API guards keep authorization on the server.
