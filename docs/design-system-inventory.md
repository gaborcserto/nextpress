# DS-01 component inventory

This is the migration inventory for reusable interaction families. Sources are the owning [Admin primitives](../apps/admin/src/ui/primitives), [Admin composed controls](../apps/admin/src/ui/components), [Admin shell](../apps/admin/src/ui/shell), [Admin features](../apps/admin/src/features), [Public UI](../apps/web/src/components/public-ui), [public content](../apps/web/src/components/public-content) and [Blog views](../apps/web/src/templates/blog). Scope and the implementation order are in the [plan](design-system-plan.md). State rules in the [specification](design-system-specification.md) apply to each applicable variant. Current risks in the table are review targets unless confirmed in the [audit](design-system-audit.md).

KEEP preserves the existing primitive, REFINE improves it in place, CONSOLIDATE aligns established consumers, CREATE fills a bounded gap, REPLACE would retire an existing control, and DEFER waits for stronger evidence. No wholesale replacement is proposed.

Consolidate style roles before merging components. Buttons and field spacing are the clearest repeated styling. Box and Section have distinct ownership even where surface styles converge. Admin and Public retain their own link, alert, menu and list implementations. The native account popover is the only proposed new overlay at this stage. Shared primitives across applications remain CSS concepts and accessibility acceptance rules until repeated implementation establishes a common API.
